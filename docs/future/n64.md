# Future work: Nintendo 64: expand layouts and preserve compiler parity

Status: **draft work plan; implementation is not complete**. Baseline: v0.19.0.

This PR adds a reviewable work plan. It does not add platform or compiler support.
Keep it in draft while implementation and the checks below remain unfinished.

## Current coverage

Implemented on native Windows and Linux: KMC GCC 2.7.2, IDO 5.3 SGI/EDG and classic cfront, IDO 7.1, C/C++ matching and fixed-address ROM exports. The v0.19.0 worker lifetime fix is already released.

## Existing programs to reuse or qualify

Reuse the pinned KMC/IDO hosts, splat, spimdisasm, m2c and target binutils. No new compiler is needed for the current paths. IDO retains explicit license acceptance.

## Work that remains

- [ ] Expand reviewed overlay, compressed-segment, TLB and data-layout fixtures; keep uncertain addresses explicit.
- [ ] Design relocatable or shiftable exports as an additional format, with a relocation inventory and size-growth rules.
- [ ] Broaden classic cfront template dependency and period C++ runtime coverage without claiming an IRIX application environment.

## Acceptance checks

- [ ] Run KMC, IDO 5.3 EDG, IDO 5.3 cfront and IDO 7.1 independently on both hosts.
- [ ] Exercise changed dependencies, invalid templates, native worker teardown and clean standalone exports.
- [ ] For any shiftable build, demonstrate changed function sizes and correct calls/data references; keep exact original rebuild verification.
- [ ] Add browser/CLI, claim, failure-reporting and standalone export coverage for any newly enabled workflow.
- [ ] Keep current required operational suites passing; new platform checks must fail rather than silently skip missing required tools.
