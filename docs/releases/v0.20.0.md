# decomp.wtf 0.20.0

This release focuses the local workbench on editable native PC source projects
for **DS, PS1, PS2, GBA and 3DS**. It includes the current main-branch work since
0.19.0 and the shared runtime fixes found while adapting Dragon Quest IV.

- Export game code, a source runtime, build configuration and owner-side asset
  preparation tools. Generated projects support GPU rendering, window resizing,
  keyboard/controller input and persistent saves, with platform-specific limits
  recorded in the project and qualification reports.
- DS includes ARM9/ARM7 static output and graphics/audio integration; PS1 supports
  ordered multi-disc games in one source project; PS2 includes EE/IOP/VU source
  paths; GBA includes ARM/Thumb desktop output; 3DS includes ARM/Thumb/VFP source
  and its bundled runtime. See the README for exact accepted input formats.
- Keep DS/3DS dual-screen presentation in the generic output; game-specific
  combined widescreen adaptations belong in the exported game project.
- Remove N64, GameCube, Wii and GB/GBC from the supported console scope and GUI.
  Remove public/collaboration controls from the local workbench. Agents remain
  optional, with local connection and agent setup instructions in the README.
- Correct DS texture state handling, use exclusive save ownership, preserve
  queued audio under load, and include runtime patch inputs in backend identity.
- Update the repository front page, GUI screenshot, setup/download documentation
  and Windows-only automated CI. Linux source builds remain a manual option.
- Update both installers to 0.20.0 and require exact-commit Windows application
  and all five native-output qualification workflows before publication.

For Windows, download **decompnet-0.20.0-windows.zip**, extract it and run
**windows.cmd**. The wheel, source distribution, installer scripts and
**SHA256SUMS** are also attached. Toolchains and optional runtime sources are
downloaded separately with their recorded checksums and licenses.

ROMs, BIOS/firmware, mobile recordings and private game outputs are not included.
A generated PC project is the starting point for a port: unfamiliar games can
still require recovery fixes, asset mapping and game-specific presentation work.
Original fixtures and bounded retail checks do not establish full compatibility
or a complete playthrough for every game. Physical GPU/audio/controller results
apply only to the hardware and scenarios recorded in their assessments.
